# Локальные модели: гайд по запуску

Этот документ — практический рецепт для режима `LLM_PROVIDER_MODE=local`:
какую модель взять под ваше железо, как поднять стек «агент + Ollama»
одной командой и почему reasoning/thinking-модели требуют осторожности.

## 1. Рекомендованные модели

Требования указаны для квантованных GGUF-версий (Q4_K_M), которые
используют Ollama/LM Studio по умолчанию. Память считается как
веса + контекст (KV-кэш растёт с длиной DOM-наблюдений — закладывайте
запас, агент шлёт длинные промпты).

| Модель | Размер | RAM/VRAM (мин.) | Для чего |
|---|---|---|---|
| **Qwen3 4B** (`qwen3:4b`) | ~2.6 ГБ | 8 ГБ RAM | Слабый VPS / ноутбук. Минимальный рабочий вариант для простых задач (навигация, клики, извлечение заголовков). |
| **Qwen3 8B** (`qwen3:8b`) | ~5.2 ГБ | 16 ГБ RAM или 8+ ГБ VRAM | Золотая середина. Уверенно следует JSON-формату агента на многошаговых задачах. |
| **Llama 3.1 8B** (`llama3.1:8b`) | ~4.9 ГБ | 16 ГБ RAM | Альтернатива Qwen3 8B без thinking-режима — хороший выбор, если не хочется возиться с отключением рассуждений (см. §3). |
| **Qwen3 14B / 32B** (`qwen3:14b`, `qwen3:32b`) | 9–20 ГБ | 32+ ГБ RAM или 24 ГБ VRAM | Сложные сценарии (динамические SPA, капчно-опасные сайты, длинные цепочки действий). |

Загрузка в Ollama: `ollama pull qwen3:4b`.

## 2. Быстрый старт: docker compose

В корне репозитория есть `docker-compose.yml`, поднимающий агента и
Ollama одной командой — с общей сетью, healthcheck модели перед стартом
агента и постоянным volume для весов:

```bash
# 1. Токен обязателен: API управляет реальным браузером
export API_AUTH_TOKEN="мой-токен-минимум-16-символов"

# 2. Поднять стек (модель выбирается через MODEL_NAME, по умолчанию qwen3:4b)
MODEL_NAME=qwen3:8b docker compose up -d

# 3. Дождаться healthcheck и загрузить веса (один раз; volume их сохранит)
docker compose exec ollama ollama pull qwen3:8b

# 4. Проверить
curl -H "Authorization: Bearer $API_AUTH_TOKEN" http://localhost:8000/health
```

Без compose (ручной запуск): поднимите Ollama/LM Studio/vLLM, укажите в
`.env`:

```env
LLM_PROVIDER_MODE=local
OPENAI_API_KEY=lm-studio          # любой непустой плейсхолдер
API_BASE_URL=http://localhost:11434/v1   # Ollama; LM Studio обычно :1234/v1
MODEL_NAME=qwen3:8b               # без ограничения формата provider/model
LOCAL_RATE_LIMIT_SECONDS=0        # опционально: убрать паузы для локального сервера
```

## 3. ⚠️ Reasoning/thinking-модели: читайте перед запуском

Qwen3 и дистилляты DeepSeek R1 имеют режим «рассуждения»: перед финальным
ответом модель выдаёт блок `<think>...</think>`. Это ломает JSON-парсинг
агента двумя способами:

1. если внутри рассуждения модель приводит пример JSON («формат такой:
   `{"tool": "click_element"}`»), поиск скобок может зацепиться за пример
   из `<think>` вместо финального действия;
2. весь диапазон «первая `{` … последняя `}`» может включить кусок
   рассуждения вместе с ответом.

**Что уже сделано в коде (defense-in-depth):** `LLMService` вырезает
блоки reasoning перед извлечением JSON. Набор тегов настраивается через
`REASONING_STRIP_TAGS` (по умолчанию `think,reasoning`; пустое значение
отключает вырезание). Незакрытый `<think>` (обрыв генерации) тоже
обрабатывается — всё после открывающего тега считается рассуждением.

**Что нужно сделать вам (первая линия защиты):** отключите thinking на
уровне сервера, где это возможно — это надёжнее любой пост-обработки:

- **Ollama**: у Qwen3 thinking включён по умолчанию — либо используйте
  вариант без рассуждений, либо задайте в Modelfile `PARAMETER think false`
  / отправляйте `/no_think` в системном промпте;
- **vLLM**: запускайте с `--reasoning-parser qwen3` (или соответствующим
  парсером вашей модели), чтобы reasoning отделялся на сервере;
- **LM Studio**: в настройках модели отключите «Enable Thinking», если
  переключатель доступен;
- универсальный запасной вариант: добавьте «/no_think» к задаче или
  возьмите модель без thinking-режима (см. таблицу выше).

Симптом того, что что-то пошло именно из-за reasoning: в логе шага
появляется `No valid JSON found in LLM response` при том, что в сыром
ответе модели действие видно глазами. Проверьте первые 200 символов
ошибки — там будет текст рассуждения вместо `{`.

## 4. Требования к железу (сводно)

- **CPU-only, 8 ГБ RAM**: Qwen3 4B, простые задачи до ~10 шагов.
- **CPU-only, 16 ГБ RAM**: Qwen3/Llama 8B — комфортный минимум для прод.
- **GPU 12–24 ГБ VRAM**: 14B–32B с заметным ускорением; скорость важна,
  потому что агент делает десятки LLM-вызовов на одну задачу.
- Диск: размер весов + ~2 ГБ на кэш Playwright/Chromium (уже в образе).

Rate-limit: в local-режиме действует `LOCAL_RATE_LIMIT_SECONDS`
(по умолчанию 1с) — он защищает локальную машину от тепловой нагрузки,
а не от внешних лимитов API.
